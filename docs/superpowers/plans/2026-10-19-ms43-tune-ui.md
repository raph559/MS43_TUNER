# MS43 Tuner UI (Live redesign + Tune tab) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the logger into "MS43 Tuner": the new visual design across the app, a redesigned Live screen (cluster dials, channel list with sparklines), and a Tune screen that opens a bin with an XDF, browses every item, edits tables, values and switches with undo, shows 2D/3D views, and saves with a backup and a TunerPro-style edit log.

**Architecture:** Editing, history, saving and the item catalog are UI-free classes in `MS43Logger.Core.Tuning`, built test-first on the plan-1 core. The polling loop moves from the window's view model into a Core `LiveLogger` that publishes samples, so later plans (Compare, live cursor) can subscribe. The Avalonia app gets a token-based theme, a shell with Live and Tune tabs, and custom-drawn controls (map grid, 3D surface, curve chart, dial, sparkline). A headless Avalonia test project renders the windows for tests and screenshots, so the UI is checked without opening windows on the user's desktop.

**Tech Stack:** C#/.NET 10, Avalonia 11.3.12 (FluentTheme), xUnit 2.5.3, Avalonia.Headless.XUnit 11.3.12 (test project only).

**Spec:** `docs/superpowers/specs/2026-10-19-ms43-tuning-design.md` (§5 look, §6.1–6.4 structure, files, Tune tab; §8 tests). **Visual reference:** the approved mockup https://claude.ai/artifact/DbvXbTSHQwYPCYhJ1v5juZ; its source with all tokens is saved as `docs/superpowers/mockups/ms43-tuner-mockup.html` in Task 6.

## Global Constraints

- Plan-1 constraints hold: `net10.0`, invariant culture in Core, XML DTD refused, originals never modified, the app never writes to the ECU, commit only when authorized.
- No new NuGet packages in `src/`; the only new package is `Avalonia.Headless.XUnit` 11.3.12 in the new test project.
- Logging behaviour stays the same: same telegrams, the same 3-timeout retry rule, the same 20 ms pause between polls, the same CSV columns.
- Design tokens, fonts and ramps come from the mockup exactly: Night `--dial #0E1116, --pane #141920, --raised #1B222B, --sunken #0A0D11, --bezel #222A34, --bezel-2 #344150, --ink #EDEAE4, --ink-2 #A3ADBA, --ink-3 #6A7480, --needle #FF6A1A, --red-zone #A9302B, --face #0F1318, --tick #C9CED6, --down #4C8DFF, --up #FF5C7A, --ok #5CC48A`; Day `#E6E9ED, #F5F6F8, #FFFFFF, #DCE1E7, #D5DBE2, #B9C2CD, #141A21, #455160, #788392, #E05206, #D65A50, #FBFBFC, #29313B, #2E6BE0, #DD3B5C, #23915A`; data ramp stops `0 #0B1E33, .18 #0F3657, .38 #11587A, .58 #1A8191, .76 #4FB3A4, .90 #A6DDC3, 1 #F2F7EC`.
- Orange (`needle`) means "now" only: live values, the needle, connection state, keyboard focus. Sentence case everywhere; no ALL-CAPS labels.
- Type: display `Bahnschrift` (fallback Inter), data `Bahnschrift SemiCondensed` (fallback Bahnschrift, Inter), tabular figures wherever digits line up.
- Never open windows on the user's desktop without asking; verify the UI through headless rendering.

## Review Focus

- Editing a value that the XDF marks read-only, or whose equation has no finite raw value: the edit is refused with a message, never written as 0; tests in Tasks 2 and 9.
- An edit that would make an axis go down: refused before any byte changes; test in Task 2.
- Closing, opening another bin, or switching XDF with unsaved edits: a prompt, never silent loss; test in Task 11.
- Saving over the opened file: the `.bak` holds the bytes as they were on disk before the first save of the session, and a failed save leaves the original untouched; test in Task 4.
- A French locale pasting `12,5` from a spreadsheet: read as 12.5; test in Task 3.
