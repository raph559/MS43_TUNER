# MS43 Map In Use Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Next to the live readout, the Tune tab says whether the ECU is using the map on screen right now: "In use", "Not in use", a blend such as "RON98 72 % · RON91 28 %", "Possibly in use" where the logger can only rule use out, or "Selection unknown". The cursor turns grey when the map is not in use.

**Architecture:** A hand-written rules file, `definitions/ms43x001_map_use.json`, sits next to the generated input map. It lists the logged selectors (frame byte, mask, the ECU variable behind it, evidence), the blend factors (from a selector or from calibration bytes), and one rule per map family: an ordered list of cases on the selectors, then each member map's weight as a product of factors. Core reads it into `MapUseRules`. At bind time `MapUseBinding` picks the rule for the table and reads the calibration factors from the open bin. On every sample it returns a `MapUse`, which `LiveTableBinding.Locate` puts on `CursorFix`. The app shows `MapUse.Text` in a new key-line label and draws the cursor in `Ink3` when the state is `NotInUse`.

**Tech Stack:** C#/.NET 10, Avalonia 11.3.12, xUnit, Avalonia.Headless.XUnit, `System.Text.Json`.

**Spec:** the task brief (map in use, weights, grey cursor, "Selection unknown", rules as data with provenance) and the firmware findings in `docs/firmware/map-use/` (`ve.md`, `ignition.md`, `loadstate.md`, `catheat.md`), summarised under "Facts" below. Builds on `docs/superpowers/plans/2026-10-19-ms43-live-cursor.md`.

## Facts this plan rests on (car bin `testdata/local/CAR_current_43X001_SP95_STAGE1.bin`, checked 2026-10-21)

Every rule below was traced in the disassembly by a read-only pass, and the key instructions were re-read here. [obs] means seen in code or bytes, [inf] means inference.

**Logged selectors** (0B B0 frame built by 0C:467E; payload offset 0 = RAM F750):

| Selector id | Frame | ECU source | ADX channel used for the check |
|---|---|---|---|
| `state` | byte 0x00 | bit0 FD2C.8 start, bit1 FD2C.9 idle OR FD42.13, bit2 FD2C.10 part load OR FD42.13, bit3 FD2C.11 overrun, bit4 FD2C.12 overrun cut. FD2C.7–.12 are one-hot [obs, state machine 0x29B6C–0x2AE10]; FD42.13 is the full-load enrichment flag, written only at 0x3D472/0x3D476/0x3D4C8 [obs]. So bits 1–2 = 01 idle, 10 part load, 11 full-load enrichment (idle vs part load hidden). | `LUTPL` (value, 0x00, 8 bit) |
| `status1` | byte 0x01 | bit1 FD9C.8 (AT in gear), bit3 FD9A.5 \| FD9E.3 \| FD9E.4 (the three cat-heating phases) [obs 0x446B2–0x446BA] | `CHSTATE` (bitmask, 0x01) |
| `vanos` | byte 0x02 | 820D bits 0–1, VANOS mode; 2 = active [obs, `DAT_04020d & 0xff03`] | `VANOSACTIVE` (bitmask, 0x02) |
| `speed` | byte 0x06 | 847F vehicle speed | `VS` (value, 0x06) |
| `activeVe` | word 0x10 | E31C, written only at 0x34938 from curve 0x7B690 on valve overlap [obs, 0x4476A `MOV R8,E31Ch; MOV F760h,R8`]; byte 0x10 = fraction F, byte 0x11 = index k | `ACTIVEVE` (value, 0x10, 16 bit) |
| `octane` | byte 0x40 | E305, the high byte of the octane adaptation word E304; the ignition code reads only E305 [obs 0x4488A] | `RONADFAC` (value, 0x40) |

**Calibration factors** (read from the open bin; flex fuel off ⇔ cal 0x70DF8 = 0, which is the car's value):

| Factor | With flex fuel off | Car |
|---|---|---|
| `e85Fuel` (8483) | (cal 0x70A10 − 128) / 32 | 0 |
| `e85Ignition` (8484) | (cal 0x70A11 − 128) / 32 | 0 |
| `e85Cam` (8486) | (cal 0x70A13 − 128) / 32 | 0 |

With flex fuel on, each factor is a curve of the ethanol content (8487, logged as FFBLEND) − 128 [obs]; that is not modelled in this plan, so the factor is unknown and the rule says "Selection unknown". The blend helper 0D:1850 computes `base + trunc((twin − base)·f/32)` with f a signed byte [obs], so a factor outside 0..1 is also unknown.

When all three cat-heating bits are clear, every clear path has already reset the retard outputs to neutral [obs]. With CHSTATE = 1 the logger cannot tell which phase runs, and the fade factors are not logged, hence "possibly".

**Left out (shown as "Selection unknown", with the reason in the data):** `ip_iga_aj_ron91/ron98` (read only while FD18.15 is set, not logged); injection timing `ip_soi_tco_1/2_*` (blend by coolant-at-start 8450, not logged; their column input 91B4 has no cursor anyway). Every other table has no rule and also shows "Selection unknown".

## Global Constraints

- `net10.0`, no new NuGet packages, invariant culture in Core; earlier plans' constraints hold.
- Originals in `../MS43LAB/bins/` are never modified; tests read `testdata/local` copies.
- The app never writes to the ECU, and logging telegrams and timing stay unchanged. Map-use evaluation runs on the UI thread inside the existing ≤ 30 Hz tick, only for the visible table.
- A missing or unreadable selector never removes the cursor: the cursor stays and the label says "Selection unknown".
- Copy, exactly: "In use", "Not in use", "Possibly in use", "Selection unknown"; a blend is `Label NN %` items joined by " · ", the viewed map first, then the others by falling weight, members at 0 left out; a weight above 0 that rounds to 0 prints "<1 %". If the viewed map has weight 0 and others don't: "Not in use · " + the list. If the viewed map is the only member above 0: "In use".
- Orange (`Now`) only for live marks. A map that is not in use draws its dot, trail and ticks in `Ink3` (a filled dot, so it stays distinct from the stale `Ink3` ring). The label is `Ink2`, or `Ink3` when not in use or stale.
- Never launch the GUI on the user's screen; verify through headless tests.
- Commit only when the user asks, with no AI co-author trailer. Do not touch the uncommitted `README.md` change from another session.

## Review Focus

- **Frame byte order of ACTIVEVE**: byte 0x10 is the fraction and 0x11 the index. A test that builds the payload from raw bytes (not from the channel's value encoding) pins it: bytes 0x47, 0x03 → "VE 3 72 % · VE 4 28 %". Task 3.
- **Full-load enrichment hides idle vs part load** (state bits 1–2 = 11): ignition part-load and idle maps must say "Selection unknown", while the AFR target says "In use". Task 3.
- **Flex fuel switched on in the open bin** (cal 0x70DF8 ≠ 0, or the user edits it while logging): every rule with an E85 factor says "Selection unknown" at once, without reopening the bin. Tasks 3 and 4 (edit the byte, raise `Changed`, rebind).
- **Logging with a definition that lacks a selector channel** (an ADX without RONADFAC): the cursor still moves and the label says "Selection unknown". Task 4.
- **Stale samples**: the label keeps its last text in `Ink3`, and a not-in-use cursor turns into the normal stale ring. Task 5.
